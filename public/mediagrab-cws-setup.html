2
Inscription

Créer le compte développeur Google

2.1 — Accéder au Developer Dashboard

  1. Ouvrir Chrome et se connecter à votre compte Google.
  2. Aller sur :
    https://chrome.google.com/webstore/devconsole
  3. Cliquer sur « Accepter les conditions d'utilisation ».

2.2 — Payer les frais d'inscription (5 $)

  1. Une bannière en haut de page vous invite à payer les frais d'inscription.
  2. Cliquer sur « Payer les frais d'inscription ».
  3. Renseigner les informations de paiement (carte bancaire ou Google Pay).
  4. Confirmer le paiement de 5 USD.
  5. Votre compte est activé immédiatement après le paiement.
Attention Ces 5 $ sont des frais uniques et non remboursables. Ils donnent accès à vie au Developer Dashboard pour publier autant d'extensions que vous souhaitez.

2.3 — Compléter le profil développeur

  1. Dans le dashboard, cliquer sur l'icône de profil en haut à droite.
  2. Renseigner :
    • Nom du développeur : nom affiché sur la fiche store (ex. : TechFixBuild)
    • E-mail de contact : pour les communications de Google
    • Site web (optionnel) : URL de votre GitHub ou site
  3. Sauvegarder.

Package

Préparer le fichier ZIP

Le ZIP doit contenir uniquement le contenu du dossier extension/, avec manifest.json à la racine du ZIP (pas dans un sous-dossier).

Sous Windows — PowerShell

# Se placer dans le dossier extension
cd "C:\Users\edwin\Documents\TechFixBuild\Logiciel\MediaGrab\extension"

# Créer le ZIP dans le dossier parent
Compress-Archive -Path * -DestinationPath "..\mediagrab-cws.zip" -Force
Vérification indispensable Ouvrir le ZIP et contrôler que manifest.json est bien à la racine, pas dans un dossier extension/. Si c'est le cas, recréer le ZIP depuis l'intérieur du dossier.

4
Obligatoire

Politique de confidentialité

Le Chrome Web Store exige une URL publique vers une politique de confidentialité. La façon la plus simple est de la publier via GitHub.

Option recommandée — GitHub Pages

  1. Dans votre dépôt GitHub, créer un fichier privacy.md (ou privacy.html).
  2. Activer GitHub Pages dans Settings → Pages → Source → main.
  3. L'URL sera du type :
    https://votre-pseudo.github.io/MediaGrab/privacy

Texte de la politique (à copier)

MediaGrab — Privacy Policy

MediaGrab does not collect, store, or transmit any personal data.

All operations — page analysis, media detection, and download — run exclusively on your local machine through a locally-installed helper application. No data leaves your device.

The extension stores only your preferences (video format, quality, codec) using Chrome's built-in sync storage. These preferences never leave your Google account.

Network requests are observed in read-only mode solely to detect embedded media streams (HLS/DASH manifests, MP4/WebM files). No request content is read, modified, or logged.

Last updated: August 2026
Conseil Rédigez la politique en anglais même si votre extension est en français : c'est la langue attendue par les reviewers Google.
5
Developer Dashboard

Créer et uploader l'extension

  1. Dans le Developer Dashboard, cliquer sur « + Nouvel article » (bouton en haut à droite).
  2. Une boîte de dialogue apparaît : glisser-déposer le fichier mediagrab-cws.zip, ou cliquer pour le sélectionner.
  3. Cliquer sur « Importer ».
  4. Le dashboard analyse le manifest et crée automatiquement la fiche. Vous atterrissez sur l'éditeur de la fiche.
Succès attendu Si l'upload réussit, vous voyez le nom MediaGrab, la version 1.0.0 et les permissions détectées. Aucun message d'erreur rouge ne doit apparaître.
Erreur fréquente Si le dashboard affiche « manifest.json introuvable », c'est que le ZIP contient un dossier intermédiaire. Recréer le ZIP depuis l'intérieur du dossier extension/.

Description longue (à copier-coller)

MediaGrab est un téléchargeur de médias qui fonctionne entièrement en local sur votre machine.

Comment ça marche
L'extension communique avec un petit serveur helper installé sur votre PC (basé sur yt-dlp + ffmpeg). Aucune donnée ne transite par un serveur tiers. Tout reste sur votre machine.

Fonctionnalités
• Téléchargement vidéo (MP4, MKV, WebM) avec choix de la résolution
• Extraction audio (MP3, AAC, FLAC, Opus) avec choix du bitrate
• Détection automatique des flux HLS et DASH intégrés dans la page
• Miniature intégrée, sous-titres et pistes audio multiples
• File de téléchargement avec progression en temps réel
• Compatible avec plus de 1 700 sites grâce à yt-dlp

Prérequis
Le helper local (MediaGrab.exe pour Windows) doit être installé séparément avant d'utiliser l'extension. Il est disponible gratuitement sur la page GitHub du projet.

Aucun compte requis. Aucun abonnement. Tout reste sur votre appareil.

Conformité

Justifier les permissions

Le dashboard comporte un champ « Justification des permissions » dans l'onglet Confidentialité. Chaque permission sensible doit être justifiée en anglais. Voici les textes à copier :

<all_urls> + webRequest
The extension observes (read-only) network requests to detect embedded media streams — HLS/DASH manifests (.m3u8, .mpd) and direct media files (.mp4, .webm, .mp3) — on any website the user visits. No request content is read, logged, or modified. This broad host permission is required because media streams are loaded dynamically by JavaScript and are not visible in the page HTML, so yt-dlp alone cannot detect them.
scripting
Used to extract the page title (via og:title or the first <h1>) and the page thumbnail (via og:image or the largest image) from the active tab. This data is used solely to name the downloaded file correctly and display a preview in the popup. No scripts are injected on background pages or in non-HTTP pages.
storage
Saves user preferences (video resolution, container format, codec preference, audio format, audio bitrate) using Chrome's sync storage so settings persist across devices and browser restarts. No personal data is stored.
notifications
Displays a system notification when a download completes successfully or fails. This is the only way to inform the user of download completion when the extension popup is closed.
activeTab
Reads the URL and title of the currently active tab to identify the media to download. Access is limited to the tab in focus at the moment the user opens the popup.
Point critique La permission <all_urls> est la plus scrutée. Si Google demande des précisions, insistez sur le fait que seuls les en-têtes de requête sont lus (URL et type de ressource), jamais le contenu.
8
Visuels

Captures d'écran

Le CWS requiert au minimum 1 capture, au format 1280×800 px ou 640×400 px (PNG ou JPEG). Vous pouvez en soumettre jusqu'à 5.

Captures recommandées

  1. Popup principal — extension ouverte sur une page avec une vidéo détectée (titre, vignette, options qualité).
  2. File de téléchargement — un ou plusieurs téléchargements en cours avec barre de progression.
  3. Page de paramètres — vue des options avancées (format, codec, dossier de destination).
  4. Détection de flux — vue « flux détectés dans le trafic » sur un site de streaming.

Méthode pour capturer en 1280×800

  1. Ouvrir Chrome, appuyer sur F12 pour ouvrir les DevTools.
  2. Cliquer sur l'icône « Basculer l'affichage appareil » (icône téléphone + tablette).
  3. Définir les dimensions à 1280 × 800.
  4. Dans le menu DevTools (⋮), choisir « Capturer une capture d'écran ».
Conseil Évitez les captures avec des données personnelles (noms de fichiers locaux, chemins Windows). Utilisez des vidéos de démonstration libres de droits pour les screenshots.

Publication

Soumettre pour révision

Checklist finale avant de cliquer « Soumettre »

  • ZIP uploadé sans erreur, version 1.0.0 affichée
  • Résumé renseigné (≤ 132 caractères)
  • Description longue complète
  • URL politique de confidentialité valide et accessible
  • Au moins 1 capture d'écran (1280×800 px)
  • Justifications de permissions renseignées
  • Catégorie sélectionnée (Productivité)
  • Langue principale définie (Français)
  • Visibilité définie : Public ou Non répertorié

Options de visibilité

OptionComportementRecommandé pour
Public Visible dans les résultats de recherche du CWS Publication officielle
Non répertorié Accessible uniquement via lien direct Bêta, tests, distribution ciblée
Privé Réservé à des utilisateurs ou domaines spécifiques Usage interne
Conseil Pour une première publication, commencez en mode Non répertorié. Une fois la révision approuvée et l'extension testée par quelques utilisateurs, basculez en Public.

Après avoir cliqué « Soumettre »

  1. L'état passe à « En cours de révision ».
  2. Google envoie un e-mail de confirmation.
  3. Délai habituel : 1 à 3 jours ouvrés.
  4. En cas de rejet, Google fournit une raison. Corrigez le point signalé et soumettez à nouveau.
10
Maintenance

Après la publication

Mettre à jour l'extension

  1. Incrémenter le numéro de version dans manifest.json (ex. : 1.0.1).
  2. Recréer le ZIP.
  3. Dans le dashboard, cliquer sur l'extension → « Importer un package ».
  4. Soumettre à nouveau pour révision.
Important Chaque mise à jour repasse par la révision. Ne publiez pas une version cassée : testez toujours en mode développeur local avant de soumettre.
